Navigation Drawer

Material Design 3 navigation drawer for app navigation. Provides modal and standard variants supporting mobile and desktop experiences with smooth animations and accessibility features. Not intended for contextual menus or settings panels — use ds-menu for action menus and ds-side-sheet for supplemental content.

Basic Usage

A simple modal drawer with navigation items. The modal variant overlays content with a scrim and traps focus until the user selects a destination or dismisses it — ideal for infrequent navigation on mobile.

Variants

Navigation drawers support two main variants for different layouts

Modal Variant

Overlay drawer with semi-transparent scrim background. Recommended for mobile and tablet layouts.

  • Use when: the app is mobile or tablet-first and navigation is accessed infrequently through a hamburger or menu button.
  • Avoid when: users navigate destinations frequently — the repeated open/close overhead degrades the experience; use the Standard variant on wider layouts instead.

Standard Variant

Persistent side drawer that remains visible. Recommended for desktop layouts.

  • Use when: the layout has enough horizontal space for a side panel and users switch destinations frequently.
  • Avoid when: screen real estate is limited — the persistent drawer crowds mobile viewports.

API

Navigation Drawer Attributes

Attribute Type Default Description
variant string 'modal' Drawer type: 'modal' (overlay) or 'standard' (persistent)
position string 'left' Drawer position: 'left' or 'right'
open boolean false Opens/closes the drawer

Navigation Drawer Methods

Method Description
show() Opens the drawer
close() Closes the drawer
toggle() Toggles drawer open/closed

Navigation Drawer Events

Event Description
ds-navigation-drawer:open Fired when drawer opens
ds-navigation-drawer:close Fired when drawer closes

Navigation Item Attributes

Attribute Type Default Description
href string '' Link destination
icon string '' Material Symbol icon name
active boolean false Highlights as current page
disabled boolean false Disables the item

Navigation Item Events

Event Description

Accessibility

Keyboard Interaction

Key Context Expected Result
Tab Drawer open Moves focus to the next focusable element within the drawer
Shift+Tab Drawer open Moves focus to the previous focusable element
Escape Modal drawer open Closes the drawer and restores focus to the trigger element
Enter / Space Focus on a nav item Activates the focused navigation item

ARIA Attributes

  • role="navigation" - Identifies drawer as navigation region
  • aria-hidden="true/false" - Visibility to screen readers
  • aria-current="page" - Marks active navigation item
  • aria-disabled="true" - Marks disabled items

Focus Management

  • ✅ Focus trap in modal variant keeps focus within drawer
  • ✅ Focus restored to trigger button when modal closes
  • ✅ First focusable element receives focus when drawer opens
  • ✅ Focus indicators meet WCAG 2.2 standards

Screen Reader Support

  • ✅ Announces drawer open/close events
  • ✅ Announces navigation item labels and icon names
  • ✅ Announces active state with aria-current
  • ✅ Announces disabled state with aria-disabled

Usage Guidelines

  • When to use: Choose the navigation drawer for apps with five or more primary destinations, hierarchical navigation structures, or when destination labels are long and need full visibility in a side panel.
  • When not to use: Avoid for fewer than five destinations — a navigation bar or rail provides faster access. Do not use a drawer as a context menu, settings panel, or filter surface.
  • Composition: Use the Modal variant on mobile and Standard on desktop. Provide a slot="header" for branding or account details. Group related items with visual separators.
  • Common mistakes: Forgetting to restore focus when the modal drawer closes. Using a drawer for non-navigational content like filters — use ds-side-sheet for that purpose.
